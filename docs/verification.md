# 验证流程

## 离线验证

在项目根目录设置 TEMP、TMP、TMPDIR 与 npm 缓存到 `work/`，执行 `npm test`、`npm run check`。记录实际结果，不将模拟 kernel 返回值当成真实 QQ 成功证据。

重点覆盖会话观察顺序、异步回调、UID/UIN 转换、发送状态、账号切换、事件缺口、长消息 ID、持久映射、CQ 转义、消息段顺序、WS 鉴权和重连。部署测试用模拟 QQ 应用目录验证入口幂等、篡改保护与精确恢复，不启动 QQ。

## 云端验证

Linux x64、QQ `3.2.35-54395` 是首批目标。Freshwater-dolphin 是独立实现，必须重新验证，不能沿用其他项目的实测结论。

1. 在工作区内构建镜像，核实 QQ 包版本与 SHA256，启动后确认真实身份与会话状态。
2. 用只读查询确认好友、群、群成员和自身资料；确认不是空列表兜底。
3. 接入目标 AstrBot，核对实际版本、WS 地址及 token；验证心跳和断线恢复。
4. 使用本次已授权的测试对象进行私聊、群聊、@、引用及新增媒体测试；逐一核对发送方、原文和消息 ID。新增对象和群管理操作需单独确认。
5. 开启 AstrBot 回复附加 @ 和引用进行组合测试，不重复发送未获授权的消息。
6. 验证账号 worker、管理进程、容器重启及连接中断，检查两个账号的隔离、无回复循环、无动作自动重发和缺口诊断。不恢复用户已取消的两小时持续观察。
7. 验证管理台鉴权、CSRF、扫码归属与真实刷新、节点鉴权和各传输角色；完整备份及恢复必须停写，并覆盖事务中断回滚。

每项记录为通过、失败或待验证，附时间、环境版本和去敏证据。发送授权只适用于已确认的对象，不扩展到无关账号或群。

## 报告与产物

验证日志、源码包、镜像包及校验文件留在 `outputs/`。报告明确区分离线测试、云端已登录、真实消息收取、真实消息发送、AstrBot 自动回复与持续运行观察；不以 socket 连通或请求入队代替业务成功。
