# 账号状态通知

在「系统设置 → 通知」管理渠道，再到「连接节点 → 通用设置 → 账号通知」选择当前账号使用的渠道并保存。渠道配置和账号选择均即时生效，不需要重启 QQ；默认没有渠道，账号通知默认关闭。

## 掉线与恢复

去抖窗口默认 30 秒，允许 0–86400 秒。只有先确认账号真正在线，随后确认离线并持续达到窗口时，才发送 `offline`；之后确认恢复在线时发送 `online`。0 表示立即通知。首次读取状态只建立基线，不会发送一轮上线通知。

手动停止、维护、卸载注入桥及应用配置造成的停止不会发送掉线通知。未知状态不会当作在线或离线；未知区间会中断尚未完成的连续掉线计时。错号、重复登录、会话切换和账号删除不会把旧会话的排队通知发送到新账号。

每个渠道独立排队，最多等待 32 条，投递超时 10 秒。失败、超时和队列溢出都会记录结果，不自动重发。恢复通知表示 QQ 已真实恢复在线，并不表示前一封邮件已送达收件箱。

## 邮件

配置 SMTP 主机、端口、用户名和授权码／密码，以及发件人与收件人。QQ 邮箱通常使用 `smtp.qq.com`、465 端口、开启隐式 TLS，密码应填写邮箱的 SMTP 授权码。

关闭隐式 TLS 时强制使用 STARTTLS，例如 587 端口；不降级为明文连接，也不关闭证书验证。收件人可填写多个地址，以逗号或分号分隔，最多 20 个。服务器接受投递才会显示发送成功；部分收件人被拒绝时显示失败，不能保证邮件最终进入收件箱。

## Webhook

向所填 HTTP(S) URL 发送一次 JSON POST，可选配置 Bearer token。不跟随重定向；只有 HTTP 2xx 算成功。接收端应按下面的结构处理，URL 可包含接收端需要的查询参数：

```json
{
  "event": "offline",
  "uin": "10001",
  "nickname": "示例昵称",
  "time": "2026-11-15T00:00:00.000Z",
  "status": "offline",
  "pid": "123",
  "error": "",
  "profileId": "example",
  "subject": "账号offline：示例昵称 (10001)",
  "body": "账号状态发生了改变。"
}
```

这是通用 Webhook，企业微信、钉钉等专用机器人若要求不同格式，需要接收端进行适配。

## 模板与凭据

主题与正文支持 `{uin}`、`{nickname}`、`{event}`、`{time}`、`{status}`、`{pid}`、`{error}`、`{profileId}`。时间为 UTC ISO 字符串，PID 为适配器 worker 进程 ID。昵称来自真实 QQ 初始化身份；未知字段为空，错误只包含安全错误码。邮件正文去除开头空白后以 `<` 开始时按 HTML 发送，变量会进行 HTML 转义。

保存 SMTP 密码、Webhook URL 和 token 后不再回显，编辑时留空保留原值。需要清除密码或 token 时使用对应的清除选项。修改 Webhook 到其他源站时，必须重新输入或明确清除原 token。

点击渠道的测试按钮并确认后，仅发送一条测试通知。测试不绑定 QQ 身份，事件为 `test`；同一渠道两次测试至少间隔 10 秒。页面显示最近 100 次投递中的最新记录，管理服务重启后清空记录。

凭据存放在工作区私有目录 `work/control/notifications.json`，不进入源码、诊断结果或账号备份。普通账号备份及恢复会关闭通知启用状态。完整账号备份保留渠道 ID 选择，但不包含全局渠道配置；跨机器恢复后，需要另外重新配置渠道。
