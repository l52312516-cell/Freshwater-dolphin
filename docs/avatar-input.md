# 个人和群头像图片输入

`set_qq_avatar` 的 `file` 与 `set_group_portrait` 的 `file` 共用安全图片导入。群头像还需要有效的正整数 `group_id`；字段、群号、账号选择和能力校验在读取或下载图片前完成。

## 接受的输入

| 输入 | 示例 | 范围 |
| --- | --- | --- |
| 已有图片句柄 | `fwd-image-0123456789abcdef0123456789abcdef` | 当前账号私有媒体目录中的图片资源，句柄原样传递 |
| 相对本地文件 | `avatar.png` | 相对于当前账号媒体目录 |
| 绝对路径或 `file:` URL | `file:///srv/freshwater/accounts/legacy/media/avatar.png` | 必须仍在当前账号媒体目录内；路径属于适配器服务器 |
| base64 | `base64://<canonical standard base64>` | 标准字母表、正确填充、无空白且可规范往返编码 |
| data URL | `data:image/png;base64,<canonical standard base64>` | 精确使用 `image/png`、`image/jpeg` 或 `image/gif`，声明类型须与图片字节一致 |
| HTTP(S) | `https://example.com/avatar.png` | 公网地址、标准端口及下方下载限制 |

例如：

```json
{"action":"set_qq_avatar","params":{"file":"avatar.png"}}
```

```json
{"action":"set_group_portrait","params":{"group_id":123456789,"file":"https://example.com/avatar.png"}}
```

单张图片最多 **10 MiB**。格式沿用现有图片模块，仅接受可识别的 PNG、JPEG、GIF，校验字节特征及尺寸；这不是完整图片解码，也不承诺 QQ 接受每一种编码变体。data URL 不接受额外 MIME 参数、其他 MIME 类型、百分号编码或非 base64 形式。

## 文件与网络边界

本地路径不得越过本账号媒体目录，不允许目录、空文件、符号链接、硬链接或读取期间发生长度变化的文件；Linux 还核对文件所有者和私有目录权限。不能使用另一账号的媒体路径或客户端电脑上的任意文件。

HTTP(S) 导入复用公共下载器的公网地址和 DNS 固定机制：拒绝内网、回环、保留地址、混合公网/私网 DNS、URL 凭据、非标准端口、重定向、压缩响应和非 200 响应。声明长度和实际流累计长度均受 10 MiB 上限约束，声明长度存在时必须与实际长度相等。图片类型由接收字节决定，URL 后缀和响应 MIME 不能绕过校验。

图片导入使用本次媒体动作剩余期限，最长 60 秒；期限覆盖 DNS 等待和流读取，网络连接另有原下载器的 10 秒超时。调用方取消时停止导入。每账号最多 4 个尚未结束的导入任务；已取消但 DNS 尚未返回的任务仍占槽位，防止积累后台任务。账号身份或会话变化会阻止后续图片提交。

最终头像派发使用专门的取消/期限检查：完成异步授权和状态核验后，在实际 bridge 调用前再次检查。每账号最多 4 个尚未结束的头像派发任务；取消不会提前释放仍在等待授权、状态或 native 结果的槽位。若已派发后发生取消、超时或回执丢失，结果视为未知，不自动重试。

## 资源与验收边界

新输入先导入当前账号私有媒体目录，生成随机 `fwd-image-*` 句柄，再交给 bridge。bridge 继续仅接受本号图片句柄，并在原账号会话内调用头像服务；原始 URL、base64 或任意路径不会作为头像调用参数跨入 bridge。

导入资源沿用账号媒体缓存限制：最多 1000 个媒体资源、总计 200 MiB，达到限制返回繁忙错误。已发出的图片句柄即使收到 kernel ACK 也保留在缓存中，避免 native 仍读取或结果未知时误删文件；需要通过现有账号缓存维护方式管理空间。只有导入失败且从未发出句柄的新资源可以立即清理。输入的已有资源和原始本地文件不会由导入器删除。

头像当前仍仅有 **`kernel_ack`** 确认，不提供头像内容读回一致性证明。本轮输入兼容只做本地测试，未部署或云测，未修改任何云端账号或群头像；两条 AstrBot 路由保持原配置。
