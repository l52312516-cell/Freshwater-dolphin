# QQ 运行版本与备份

运行身份由 Linux/x64、QQ 完整版本与 build、安装包 SHA256、实际 wrapper.node SHA256 和接口契约共同决定。`3.2.35-54395` 的历史参考身份记录在 `src/qq/runtime-profile.cjs`；摘要描述已使用的产物，不等于腾讯签名。官方网页只写 `3.2.x` 不能证明完整构建。

## 版本选择

管理台的 QQ 账号页提供“QQ 运行版本”。先把候选 `.deb` 放入运行环境的 `work/qq-imports/`，填写文件名及独立核对的 SHA256 进行登记。管理台不接受任意系统路径，也不会执行安装包内的维护脚本。

安装包冻结到 `work/qq-packages/<packageId>/QQ.deb`，清单保存完整版本、架构、包和 wrapper 摘要。账号保留独立真实目录；不会通过符号链接共享可写 QQ 程序。未知构建必须明确启用实验兼容，首批只开放经结构检查的身份、联系人／群读取、消息读取及纯文本收发。其他接口单独关闭，不尝试旧 native 偏移，也不自动重发失败写入。

稳定模式只在完整指纹匹配时继承对应历史证据。旧配置缺少身份时显示未认证；方法存在和当前可用不代表业务已验证。Windows 宿主运行 Linux 容器，不产生 Windows QQ 9.9.x 的兼容声明。

受管理台会话和 CSRF 保护的接口：

- `GET /api/qq-runtimes`：包清单和账号选择。
- `POST /api/qq-runtimes/import`：`{file:"QQ.deb",expectedSha256:"..."}`。
- `POST /api/accounts/:id/runtime`：`{packageId,profileId,experimental}`。

不能通过普通账号配置 PATCH 绕过版本切换事务。

## 切换与恢复

切换只锁目标账号：预检包和空间，停止并核实写入者退出，checkpoint 消息映射，暂存新程序与状态副本，再逐目录交换。运行账号必须确认原 QQ 身份后才恢复管理授权；这期间原路由配置保留。登录未确认、进程退出或提取失败会恢复旧程序、状态和账号配置。

`work/control/runtime-switches/` 保存持久恢复日志。交换或回滚被中断时，下一次启动先恢复，未确认恢复完成的账号保持阻断。成功切换的原始状态保存在返回的 `work/runtime-switches/…` 私有快照中；这些快照包含登录信息，应按敏感数据保管。剩余空间不足时不进行版本切换。

## 备份 v3

新备份按账号记录 runtime 身份，兼容导入旧 v2 基线备份。

- 普通备份只迁移脱敏后的消息 ID 映射，保留目标账号自己的 QQ runtime，不能用于 QQ 数据回滚。
- 完整恢复在更改账号前要求原精确安装包可用，并将对应 QQ 程序目录与登录／配置／映射一起纳入恢复事务。
- 身份不完整的 legacy 备份标为未认证；不会因版本字符串相同而补造已认证摘要。

完整归档仍有原有体积上限，不能替代版本切换时的完整本地快照。新 QQ 迁移过的数据库不能直接交给旧 QQ 使用。
