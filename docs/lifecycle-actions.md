# 单账号退出、重启与缓存清理

`bot_exit`、`set_restart`、`clean_cache` 均不接受动作专用参数，成功 `data` 为 `null`；通用 `self_id` 如提供，必须为当前账号。没有参考 `delay` 参数，也不接受进程号、命令或清理路径。

| action | 实际范围 |
| --- | --- |
| `bot_exit` | 通过管理进程将当前账号的持久目标状态设为 `stopped`，再沿现有进程所有权校验和停止流程退出该账号。其他账号及管理服务继续运行。 |
| `set_restart` | 通过管理进程停止并重新启动当前账号；持久目标状态始终为 `running`，不会在停止与启动之间写入 `stopped`。 |
| `clean_cache` | 实际清除当前账号流式文件 manifest 登记、且未被活动操作占用的临时文件，完成清理后返回。 |

## 响应与执行顺序

退出与重启要求受管理的 worker，以及能报告响应发送完成的传输入口：公共/内部 HTTP、正向 WebSocket 或反向 WebSocket。直接调用 service 而没有完成响应的钩子时明确不支持。能力键为 `managerLifecycle`；缓存清理单独使用 `cleanCache`，要求配置账号媒体目录。

管理进程通过仅绑定 `127.0.0.1` 的内部通道接收固定的停止/重启请求。预约绑定当前账号授权、会话 epoch 和具体子进程对象，并从预约至执行结束持有现有账号操作锁；与其他账号操作冲突时返回繁忙。旧会话或旧进程的预约不会停止后来替换的进程。

worker 先完成最终会话检查并发送 OneBot 成功响应；HTTP `finish` 或 WebSocket 发送回调成功后才请求 commit。管理进程在 commit 中先持久化目标状态，再撤销账号授权、等待在途操作收敛并停止受管理进程。响应失败、断线、动作最终失败或未及时完成响应的预约会取消/到期，不执行生命周期变更。

因此退出与重启的 `null` 表示异步受理，不表示已停止、已重新登录或 QQ 已上线。成功响应发送至 commit 完成之间存在崩溃窗口：管理进程在此期间退出，操作可能不执行；commit 后发生的停止/启动失败也不能改写已经发送的响应，应查看管理界面中的账号状态。commit 成功后的目标状态已持久化；重启过程保持 `running`，由既有管理器恢复流程处理后续启动。服务不会因此调用全局 `process.exit`，也不提供任意进程操作入口。

## 缓存保留范围

`clean_cache` 复用 `clean_stream_temp_file` 的账号内 manifest 清理，不扫描任意缓存目录。活动上传和传输占用的文件保留，未登记文件、账号登录资料、QQ 数据库及 QQ 媒体树、消息 ID 映射、媒体签名 key 和闪传恢复日志均保留。管理界面的停机媒体清理是另一项范围更广的操作，不由该接口调用。

离线测试已覆盖账号隔离、持久目标状态、旧授权/进程拒绝、锁冲突、预约超时、持久化失败、HTTP/正反 WebSocket 的响应顺序，以及缓存对活动文件和恢复资料的保留。本轮未调用真实账号的退出或重启；当前验证证据见 [后续完善记录](qqapi-remaining-20261116.md)。
