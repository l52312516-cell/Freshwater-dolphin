# QQ 与 OneBot 能力边界

本文列出当前源码的实际边界。`get_capabilities` 的 38 项标准动作、20 类标准消息段和 4 类事件是兼容性清单，不代表全部实现。`implemented` 表示存在实现，`available` 还取决于当前真实会话、QQ 方法和配置；离线测试通过不等于在当前目标 QQ 中验证通过。

首批 QQ 目标固定为 Linux x64、3.2.35-54395。其他 QQ 版本不自动猜测接口签名。以下新增能力都必须由对应账号的实际测试单独确认，不能继承旧项目的测试结论。

## 消息与媒体

| 能力 | 当前实现与具体限制 |
| --- | --- |
| 文字、@、引用 | 保留段顺序和空白，私聊先转换真实 UID，引用刷新原始定位。发送只认对应 peer、关联 ID 和 `sendStatus === 2` 的确认。 |
| 普通表情 | 支持稳定的内置表情类型。动态贴纸、骰子和猜拳等需要额外元数据，不把它们伪装成普通表情。 |
| 图片发送 | 接受账户私有媒体目录内非空的 PNG/JPEG/GIF，以及规范 `base64://` 图片。单张及整条消息内嵌图片解码总量最多 10 MiB；读取真实尺寸和 MD5，再交给 QQ 原生上传。内嵌图片先转成本账号私有短路径，发送结束或失败后清除导入副本，不把 base64 放入文件 RPC。远程 URL、闪照和表情包输入仍不支持。 |
| 图片接收、`get_image` | 查询精确消息和 element ID；本地缺失时调用 QQ 的真实下载接口，先装等待者，再核对完成回调、错误码、大小、MD5 和目录。优先通过按账户签名的短期资源 URL 交付；官方图片 URL 缺少 rkey 时，可按全局配置依次请求回退服务，区分群聊与私聊、按账号缓存有效 key。没有真实 key 就明确失败。 |
| 文件上传扩展 | `upload_group_file`、`upload_private_file` 接受账户媒体目录内最大 50 MiB 的本地文件，上传到会话根目录，保留真实文件名并等待 QQ 发送成功。暂不支持子目录、远程下载或任意宿主机文件。 |
| 文件消息段 | `file` 为扩展消息段，发送复用已验证的本地文件上传链路，每条消息只允许一个文件段，不拆分混合消息。`get_msg` 和历史查询可返回真实文件 ID、文件名、精确大小；自动入站文件事件、文件下载和资源导出尚未实现，不从文件名猜下载 URL。 |
| 语音、`get_record` | 出站支持账户本地 MP3/WAV/QQ SILK，普通 FFmpeg 解码和 SILK WASM 编码，真实 PCM 样本计时与 RMS 波形；最长 600 秒，源文件 50 MiB。工具和 native 方法均存在时 `can_send_record` 才为 true。入站完整 SILK 可经实际下载导出；`get_record` 输出格式转换仍不支持。真机结果以本轮报告为准。 |
| 视频 | 入站支持完整 MP4/WebM 原始文件下载，最大 50 MiB。QQ 通用下载明确失败时，可按精确消息/元素查询 QQ 原生视频 URL，仅从受限的官方域名单次下载，验证大小、MD5、完整容器后交付短期签名 URL。出站支持本账号目录内最大 50 MiB、600 秒、4096×4096 的单视频轨 H.264 MP4，读取真实尺寸和时长并解码真实 PNG 封面，再交 QQ 上传并等待确认；只允许单个视频段，不转码、不生成默认元数据。真机结果以本轮报告为准。 |
| 合并转发、`get_forward_msg` | 接收真实 16 型合并转发并登记账号及会话绑定句柄；读取文字、普通表情、具有真实官方 HTTPS 资源定位的普通图片和已观察到的嵌套节点，保留作者与空白。图片按自身 appid 获取所需 rkey，不将子节点冒充主会话消息下载。`get_forward_msg` 同时提供标准 `message` 节点和常用 `messages` 形状；`qqapi_get_forward_messages` 可从已知消息 ID 刷新真实根。合并内语音、视频及引用上下文仍未验证，整条查询明确失败。`qqapi_message_forward` 仅普通转发已有消息，返回 kernel 回执，不伪造目标消息 ID。`send_group_forward_msg`、`send_private_forward_msg` 已接入本账号作者的文字/base64图片自定义节点（1–100节点）；先在自聊发送全新源消息，目标合并资源逐项核对来源元组后返回真实持久消息 ID；新增链路的真机结果以接口云测报告为准。 |
| 音乐卡片 | 出站接受 QQ/网易云歌曲 ID 或自定义链接、音频和标题；使用全局显式配置的签名服务，校验音乐卡片后签发绑定账号会话、目标和卡片内容的一次性桥接凭据，再调用 QQ 原生发送并等待确认。签名服务故障、篡改、跨目标、旧会话、重复凭据和超时均报错，不提供通用 JSON 后门。离线链路通过不能代替真实卡片验证；第三方签名服务可用性需单独核验。 |
| 分享与 JSON 卡片 | 入站合法 Ark JSON 以 `json` 段保留原文。固定 news 分享卡片虽能被 QQ 受理并查询，但两轮真机客户端均显示“发送者版本过低”，因此 `share` 出站停用并明确返回不支持，不能把保存成功当展示成功。实验模板与凭据校验仅保留离线测试，不提供任意 Ark 或音乐签名旁路。通用 JSON、XML 和位置等出站段仍不支持。 |

图片、语音和视频导出统一最多保留 1000 个文件、总计 200 MiB；达到限额时明确返回繁忙，不静默删除仍可能被引用的资源。文字和请求动作默认总期限 10 秒，媒体转换、收发和文件上传默认 60 秒，下游转换、下载和发送共用剩余预算，不分步骤重新计时。历史消息扩展只支持向较早方向分页，游标使用持久化 OneBot ID 或绑定账号会话的原始页面游标；原始 QQ 长整数序列以字符串和 BigInt 比较，分页完整性未知时 `has_more` 为 `null`。历史页跳过精确属于本账号的 `sendStatus === 0` 失败记录及已验证系统灰条，分别返回 `skipped_failed_count`、`skipped_system_count`；对已验证的原生撤回占位记录另返回 `skipped_recalled_count`，保留原始分页位置，不给未送达记录分配成功消息 ID。

## 群与用户操作

| 能力 | 当前实现与具体限制 |
| --- | --- |
| 好友、资料、群、群成员 | 保留实际返回的可选字段；完整列表和异步详情必须获得正确的真实结果，查询失败不会伪装成空列表成功。 |
| 撤回与撤回通知 | 撤回动作刷新原始记录并等待实际撤回更新。通知要求存在真实操作者 UID、原始定位和有效时间，使用原 OneBot ID，并单独持久化通知去重。 |
| 戳一戳通知 | 识别目标 QQ 版本的 `1061` JSON 灰条，将真实发起者和目标 UID 转换为 UIN，输出 `notify/poke` 通知。不会伪装为文字消息或分配消息 ID；按账号、会话、聊天和原始事件 ID 有界去重。未知灰条明确跳过。群聊实时接收已通过双账号验证，私聊仅验证历史中已知系统灰条的过滤，实时戳一戳变体仍待实测；发送戳一戳仍不支持。 |
| 群名、全群禁言、成员禁言、退群 | 使用类型明确的普通 kernel 方法，参数和真实成员权限校验后等待结果；解散群未实现。 |
| 群名片、管理员 | 原生方法返回 void，因此先装成员等待者，再调用一次变更并刷新成员；只有当前 group/UID/UIN 和期望值匹配才成功。超时不自动重试。 |
| 踢人 `set_group_kick` | 使用已核实签名的普通 `kickMember`，不猜测 V2 标记。调用前核对完整强制刷新成员快照、真实 UID/UIN 和角色权限；只派发一次，再读取完整强制刷新快照确认该成员由存在变为缺席。void、请求编号和其他完成信息均不代表成功；明确非零错误拒绝，缺席未确认则失败或超时。目标原本不在群时返回未找到，不冒充本次成功。当前新增实现已离线验证，Freshwater 云端行为需另行验证，不能继承 QQApi 的结果。 |
| 专属头衔、匿名群能力 | 缺少可靠原生签名或确认事件，保持不支持。 |
| 资料点赞 | `send_like` 先将真实 UIN 转换成 UID，固定一次 `setBuddyProfileLike` 调用；只在明确成功且实际次数精确匹配时返回成功，部分成功或未知结果不补发。当前会话须具备实际 profileLike 服务。 |
| `@全体`额度 | `get_group_at_all_remain` 从真实 group 服务返回权限和群／账号剩余次数，保留零额度和官方提示。 |
| 群文件列表和详情 | 支持根目录、指定目录分页与精确文件详情；列表需真实请求编号和匹配回调，保留分页和 uint64 文件大小。目录条目不计入 QQ 返回的文件总数。新增真实文件计数、根文件夹创建、文件夹和文件改名、文件移动/删除/转存及文件夹删除，严格核验嵌套业务回执及批量完整结果。`get_group_file_url` 经原生 MSF 通道（`OidbSvcTrpcTcp.0x6d6_2`）返回真实官方 `ftn_handler` 下载 URL，仅接受 `*.qq.com` 官方域；下载令牌短期有效，按次实时获取、不缓存。`get_group_file_system_info` 经原生通道（`OidbSvcTrpcTcp.0x6d8_3`）返回真实 `total_space`/`used_space`（uint64，超出安全整数以十进制字符串表示）；不含 `file_count`（用 `get_group_file_count`），不能把请求编号当容量。真机结果以接口云测报告为准。 |
| 自身资料及群备注 | `set_qq_profile` 支持昵称与签名，`set_group_remark` 修改本账号群备注。先读取真实原值，修改后按身份、目标与请求字段核对回读；昵称和签名在共同的十秒期限内每 250ms 只读确认，确认前一字段后才发送后一字段。未知结果不自动重发或回滚，组合修改部分完成如实报错。 |
| 群荣誉 | 缺少已验证的普通 kernel 契约，不借用原私有项目、网络封包实现或硬编码凭据。 |
| cookies、CSRF、credentials | 暂不导出账号凭据，不把会话初始化数据、登录票据或诊断日志作为协议返回。 |
| 重启与缓存清理 | 不允许 OneBot 远程请求任意进程操作或删除登录数据。受控的应用管理由管理进程承担，标准 `set_restart`/`clean_cache` 目前不实现。 |

好友/群请求处理、备注、分组、最近联系人和已读能力由独立 social 模块维护，其实时状态以生成的能力矩阵和 `get_capabilities` 为准。审核先安装绑定真实申请的等待者，操作完成后主动只读刷新对应申请列表；刷新请求成功仍不能代替实际申请状态确认，超时后同一 flag 不重复派发。不能确认参数语义、请求有效性或最终状态时必须返回不支持/失败，不能假定执行成功。

## 本轮新增动作与成功含义

本轮接入 13 个动作，其中 `get_forward_msg` 是标准动作，其余 12 个是扩展；不能把它们写成新增 13 个标准或扩展动作。以下是源码返回语义，逐项云端验收结果另外记录，不因存在实现就视为所有账号、权限或参数变体均已验证。

| action | 成功返回与确认范围 |
| --- | --- |
| `get_forward_msg` | 输入已观察到、绑定当前账号及会话的 `id`，返回 `message` 节点数组与兼容 `messages`；过期或其他账号句柄拒绝。 |
| `qqapi_get_forward_messages` | 输入已知 OneBot `message_id`，回读真实 16 型根消息，返回当前 `id` 及上述两种节点形状；可用已观察到的 `parent` 读取同一根下的嵌套节点。 |
| `qqapi_message_forward` | 将同一真实会话内的 1–50 个已有 `message_ids` 普通转发到唯一群或私聊目标。返回 `confirmed: true`、`confirmation: kernel_ack`、源 ID 与目标；没有目标消息 ID，也不代表收件端已收到或展示。 |
| `get_group_file_count` | 返回指定群的真实 `group_id`、`file_count`；不是空间容量。 |
| `create_group_file_folder` | 仅根目录创建；核对真实文件夹 ID、请求名称及 native GroupItem 的群号和类型后返回 `folder_id`。 |
| `rename_group_file_folder` | QQ 明确受理后，按原文件夹 ID 完整分页回读根目录，名称实际匹配才成功 `data: null`。默认 SDK echo 不能替代真实回读；总期限内只轮询查询，不重发改名。 |
| `delete_group_folder` | 核对明确的嵌套业务成功回执，成功 `data: null`；未知结果不重发。 |
| `delete_group_file` | 单文件或 1–100 个文件批量删除；成功列表必须精确覆盖全部请求且失败列表为空，成功 `data: null`。 |
| `move_group_file` | 采用真实源、目标目录与上述完整文件回执，成功 `data: null`；部分成功报错。 |
| `trans_group_file` | 返回 `group_id`、原 `file_id`、`save_busid`、`save_file_path`。QQ 可能将转存后的文件换成新 ID；云测应按 `save_file_path` 在目录中重新定位并查询真实元数据。`save_busid` 与目录中的 `busid` 不能直接等同，后续文件操作使用重新查询到的当前目录 `busid`。未据此验证保存后的文件实际下载、内容或客户端展示；`save_file_path` 不是下载 URL。 |
| `rename_group_file` | 采用真实文件 ID、busid、父目录和新名称，核对明确业务回执及返回的可选文件身份，成功 `data: null`。 |
| `set_qq_profile` | 仅支持 `nickname` 与 `personal_note`，按本账号身份回读确认所请求值后成功 `data: null`；组合修改部分完成如实报错。 |
| `set_group_remark` | 修改当前账号的群备注，按群号回读确认实际值后成功 `data: null`；不是修改群公开名称。 |

合并转发中的图片必须具有真实官方资源定位，缺少 rkey 时仍依赖显式启用且可用的 rkey 服务；未配置或服务失败时返回 `RKEY_UNAVAILABLE` 等明确错误，不剥掉图片返回残缺文本。仅文字合并样本通过不能证明含图片合并通过，图片数为零时的下载校验也不是图片实测证据。合并内语音、视频、引用仍未验证。`send_group_forward_msg`、`send_private_forward_msg` 仅支持本账号作者的自定义文字/base64图片节点，最多100节点、1000段、64KiB文字及10MiB合计图片；拒绝其他作者、id引用节点、嵌套、任意路径或URL。接入实现与真机通过的参数范围须分别记录。普通已有消息转发与自定义合并创建是不同能力。

群文件修改动作都只派发一次，超时或不完整结果不会自动重试；读取动作的分页与详情查找仍有明确上限。群文件下载 URL 与群空间容量已由原生 MSF 通道提供（见 `get_group_file_url`、`get_group_file_system_info`）；未提供真实契约的文件操作继续不支持。私聊文件下载 URL（`0xe37_1200`）proto 已源码确证并离线验证，但真机查询对已发送文件超时，需接收态文件实测，尚未接入为可用动作。群文件夹和文件的所有参数、批量及权限变体都需要单独实测，单个测试对象通过不能替代这些覆盖。

## 四个验证阶段的剩余工作

1. **QQ 原生能力验证**：逐项在目标版本验证新增图片下载、文件上传、历史、撤回和群操作；管理动作需选择允许修改的测试群并单独授权。登录二维码与发送对象、次数按本次测试授权确认。
2. **OneBot 完整兼容**：未支持动作和媒体保留明确错误；缺少稳定签名、相关 ID、编码或真实下载结果时不扩展能力宣称。需要实际 aiocqhttp/AstrBot 验证新增事件与参数格式。
3. **管理与隔离**：多账号管理、鉴权、资源下载地址与账户生命周期需验证撤权、切号、过期签名和交叉账号访问；进程活着或 WebSocket 连通均不能代替 QQ 已上线。
4. **故障场景和交付**：变更后的版本需要独立完成断线重连、进程重启后 ID 恢复、账号切换隔离、超时不重发和队列溢出检查；每项分别记录模拟测试、目标环境结果或未验证状态。用户已取消两小时观察，本轮不恢复该等待要求。源码包、Docker 构建和真实云端镜像验证也分别列出，未执行的项目不记为已交付。

完整可用性仍取决于当前账号 QQ 是否完成初始化。下载及发送没有确认时返回超时，可能已执行的发送不自动重试；队列溢出和断线缺口只记录诊断，不承诺完整补发。

内部构建探测只允许从真实群消息调用有限的 QQ 合并构建接口，结果仅供私有 RPC 诊断；它没有开放新的 OneBot action，也没有授予任意原生消息元素的发送权限。只有取得有效合并资源、完成目标绑定和真实发送确认后，才能将对应发送变体标记为可用。

### AstrBot 合并发送

两个合并发送 action 共用正式动作分发、账号授权和60秒媒体期限。整批校验及媒体准备完成后才在自身UID会话暂存节点，然后仅调用一次原生合并发送；QQ返回0不代表成功。真实目标根、发送状态、资源及节点的来源序列/随机号/作者/时间/完整支持元素均需回读匹配。结果不明不重发。暂存消息保留在官方QQ自聊历史，不自动撤回；失败可能已经产生部分暂存或目标消息。未知段整体拒绝，不降级为残缺文本。发送端完整Ark合并根也可注册账号会话句柄并查询；普通Ark仍按JSON处理。

自定义节点的 `nickname` 作为 `senderShowName` 传给 QQ；QQ 可能回填真实昵称或名片。查询保留 QQ 返回的真实名称，不伪造请求中的名称，发送确认仍严格验证真实作者与全部源元组、消息元素。
