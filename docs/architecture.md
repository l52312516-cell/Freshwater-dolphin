# 运行结构与内部接口

## 管理服务与账号实例

一个容器运行常驻管理服务，管理台默认端口为 `4090`。管理服务提供 WebUI、管理 REST、状态与日志 SSE、账号编排、备份和通知；每个账号的 OneBot 服务在独立 Node.js 工作进程中运行。

每个实例由稳定的 `profileId` 标识，拥有独立 QQ 程序副本、Xvfb 显示、DBus 会话，以及 `work/accounts/<profileId>/` 下的 HOME/XDG、RPC、消息映射、日志、媒体和运行状态目录。账号启动脚本管理这一实例的进程组；一个账号退出不主动停止其他账号，但同容器资源耗尽仍可能影响整体。默认最多同时启动两个账号，启动前检查包括容器约束在内的可用内存；此检查不构成资源预留或操作系统级隔离。

管理服务依据持久化运行意图依次恢复账号，手动停止或维护中的账号保持停止。真实 QQ 身份确认后，管理服务校验预期账号与重复登录，再写入绑定实例、QQ 号和会话 epoch 的授权。工作进程在连接、上报和执行动作时验证授权；未知实例不会回退到其他账号。

登录采用按需开启的内嵌 noVNC，远程会话绑定账号进程世代，最长五分钟。x11vnc 仅监听回环地址，经管理认证及同源 WebSocket 转发；账号初始化并获授权后关闭远程会话。QQ 确认在线和身份匹配后隐藏窗口并启用后台渲染节流，QQ 主进程、native 会话、Xvfb 和 DBus 保持运行。此方式不保证固定内存降幅。

## OneBot 连接与业务链路

QQ 官方应用 → 入口观察与 kernel 接口 → 账号私有文件 RPC → 独立 OneBot 工作进程 → 各账号配置的连接节点。

QQ 会话由官方应用创建和初始化，接入代码观察这一过程后安装监听。管理接口不能执行任意 JavaScript、shell 或原始 kernel 调用；文件 RPC 使用固定操作白名单，不向网络直接开放。

支持以下四种节点，复用同一套动作处理、校验和消息转换：

| 节点 | 连接方向 |
| --- | --- |
| HTTP API | 下游经管理服务调用账号工作进程 |
| HTTP 事件上报 | 工作进程向配置的 HTTP(S) 地址发送事件 |
| 正向 WebSocket | 下游经管理服务连接账号工作进程，支持 Universal、Api、Event 角色 |
| 反向 WebSocket | 工作进程主动连接 AstrBot 等下游的 WS(S) 地址 |

HTTP API 和正向 WS 对外使用 `/onebot/<profileId>/<nodeId>` 前缀，下面保留动作或角色路径。管理服务转发到相应工作进程在 `127.0.0.1` 上动态分配的网关端口；节点验证自己的 OneBot token，不接受管理台 Cookie 代替。管理台动作入口使用单独的会话授权凭据。结果只返回原请求连接，节点独立排队、限流和记录连接状态。

## 文件 RPC 版本 1

桥目录必须为当前用户私有的绝对路径。请求原子写入 `requests/<id>.json`，结果写入 `responses/<id>.json`。请求包含 `version: 1`、`id`、固定 `method`、对象 `params`、绝对毫秒期限 `expiresAt`；响应为 `{version,id,ok:true,result}` 或 `{version,id,ok:false,error:{code,message}}`。

当前白名单包含 24 个操作：

- 状态与资料：`status`、`resolve`、`user`、`friends`、`groups`、`groupInfo`、`groupMember`、`groupMembers`。
- 消息与媒体：`getMessage`、`history`、`recall`、`prepareMedia`、`prepareMusic`、`prepareShare`、`receiveMedia`、`imageInfo`、`sendMessage`、`forwardOperation`。
- 管理与互动：`groupAction`、`socialQuery`、`socialAction`、`interaction`、`groupFiles`。
- 事件读取：`events`，由 RPC 服务处理。

白名单表示允许调用的内部操作，不等于当前 QQ 会话支持其全部参数或底层能力。发送及其他敏感操作绑定 `expectedEpoch`；能力缺失、权限不足、无效参数和查询失败均按真实结果返回错误。

RPC 服务和工作进程的 RPC 客户端默认各允许 32 个在途请求，单个 RPC 文件最多 2 MiB。每个连接节点默认允许 16 个并发动作，可配置为 1–128；管理台内部动作入口上限为 16。多个节点共享同账号的 RPC 容量，达到限制时返回忙碌，不承诺为状态或事件轮询预留专用槽位。普通动作默认十秒，媒体动作默认六十秒；底层具体操作还受各自期限约束。

`events` 使用桥实例标识与游标，返回有序事件和缺口标志；业务事件携带账号和会话 epoch。桥内队列默认最多保留 1000 条、60 秒、8 MiB，写入、读取和轮询时清理过期项。工作进程及网络节点还各有独立队列和期限；发生丢弃、游标落后或实例变化时报告缺口，不代表已完成业务恢复，也不保证完整补发。

群列表、群详情及群成员查询先安装等待者，再调用 QQ，并匹配真实回调。相同查询可以合并为一次原生请求，共享观察周期至多十秒；每位调用者保留独立期限和取消信号，最后一位等待者离开后清理共享观察。

取消或超时会停止本项目的等待、移除可清理的监听，并阻止迟到结果被报告为成功；不能据此保证撤销已经交给 QQ native 的操作。发送或管理动作结果不明时不自动重试。

`forwardOperation` 提供固定的已有消息普通转发、已观察合并资源读取和 `customMerge` 自定义文字/图片合并。`customMerge` 使用当前账号新建的自聊源消息及目标资源完整元组回读确认，不依赖QQ合并时会清空的guildId，不提供任意原生调用。普通转发扩展返回精确的 kernel 回执，不生成未知的目标消息 ID；它不创建自定义合并资源。合并转发句柄绑定账号、epoch、真实根消息和已观察父节点，最长一分钟，不能以任意资源字符串查询。

## 消息、身份与状态

私聊目标以 kernel UID 表达，群目标以群号表达。OneBot 的 QQ 号必须经过真实转换；同时提供 UIN/UID 也要核验对应关系。双向身份缓存最多保留两万对，淘汰后重新查询，不改变持久消息 ID。

原生长整数消息 ID 全程保留字符串。OneBot 消息 ID 按账号从 `1` 分配至 `2147483647`，原子持久化且不复用；耗尽时明确失败。默认保留近期一万条消息的完整内容，旧记录保留 ID、定位及去重标记，因此此条数上限不等于整个映射文件的容量上限。

发送动作先验证全部消息段，等待目标、账号和关联标识均匹配的 `sendStatus=2`。收到的自身回显不作为普通消息再次上报。引用只能定位同一会话的真实消息，不能跨账号或以未知定位发送。

`ready` 表示观察到会话初始化完成；能力标志还检查具体方法和监听是否可用。`online` 来源于真实主会话状态，未知值在内部保留为 `null`。进程存活、管理台可访问或网络连通均不能证明 QQ 在线；过期或无法读取的健康报告不能继续显示为已确认在线。

管理控制目录、消息数据目录和桥目录使用进程归属锁，账号子进程另有归属记录；Linux 核对进程启动标识以处理 PID 复用。恢复锁遇到并发或损坏时明确失败；若留下 `.recovery` 目录，须先确认没有相关进程运行，再人工处理，不能盲目清理在线实例。

以上描述当前源码的结构与边界。离线测试或代码存在不等于真实 QQ 能力已通过验证；云端验证范围以对应报告中的账号、QQ 版本、操作及结果为准。
