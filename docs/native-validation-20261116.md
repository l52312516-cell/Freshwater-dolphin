# 原生通道与目标 QQ 验收（2026-11-16）

本文为可公开的脱敏验证摘要。目标固定为 Linux x64、Node.js 22.23.5、QQ 3.2.35-54395、Freshwater 0.2.0-alpha.2，使用两个独立已登录测试实例。不能据此保证其他 QQ 版本、全部权限或文件大小和参数变体。完整发布范围见 [0.2.0-alpha.2 验收摘要](releases/0.2.0-alpha.2.md)；原始运行证据与私有工作区报告不随 Git 仓库提交。

## 正式构建与离线验证

原生模块从本项目 `src/native/msf-capture.c` 在 Docker 独立构建阶段编译，使用同版 Node 头文件和 `-Werror`。构建及容器入口分别验证 manifest、源码与二进制 SHA256，并独立加载导出。QQ 函数入口、回调复制和调用者释放三处指纹全部匹配才安装钩子；ELF 可读范围、执行权限或恢复检查失败时停止启用。

主机源码与运行镜像中的 `src/`、package 文件、原生构建工具及 `deploy/` 已核对相同内容摘要。addon 摘要描述本轮构建，不保证其他编译器和构建环境产生逐字节相同的二进制。此前 native-clean 阶段的 1052 项测试是历史批次，不与最终 1166 项累加。

临时 probe RPC、无引用的 `msf-probe.c` 和旧 loader 已从正式源码及运行镜像移除。固定命令、参数白名单与当前会话约束保留，不开放任意 JavaScript、kernel 或 SSO 调用。受限内部研究实现不属于公开 OneBot 能力。

同包静态指令已核实 shared_ptr 参数由调用者持有、被调用者复制，调用者归还参数引用；真实请求完成后的引用清理与未决计数相符。该证据支持当前调用契约，不等于对所有 QQ 内部异常路径的形式化证明。

## rkey、并发与真实媒体下载

| 场景 | 真实业务结果与边界 |
| --- | --- |
| QQ 自身获取 rkey | 两个账号均经固定 `nativeRkey` RPC 返回 type 10（私聊）和 type 20（群聊），响应有效期 3420 秒；记录仅保留类型、时间、长度及摘要，不发布 key。 |
| 并发和短期限 | 每个账号四个并发请求成功；1 毫秒期限明确超时；结束后 `nativeStatus.liveRequests` 为 0，会话和在线状态正常。短期限失败不等于已抓到服务端迟到包，迟到关联主要由离线测试覆盖。 |
| 自然到期重取 | 同进程、同会话等待实际 TTL 到期，没有清缓存、改时钟或外部回退；到期后原生重取分别约 1528/1501 毫秒，后续图片 HTTP 200、大小和 MD5 均匹配。重启或清缓存不冒充此项证据。 |
| 含图合并读取 | 两个账号经标准 `get_forward_msg` 和扩展读取同一份 35 节点、16 图样本，完整内容一致；全部图片真实下载并核对 MD5。早期两节点单 JPEG 样本另有校验，不与较大样本混淆。 |
| 私聊文件查询 | 正式 OneBot `get_private_file_url` → 固定 RPC → QQ 原生请求取得资源，实际下载 56041 字节，大小及前 10 MiB MD5 与原消息一致。 |
| 新私聊文件入站 | 新消息实际转换事件自动附 URL，直接以事件 URL 下载校验；取证前未用 `get_msg` 或文件查询刷新。不单独证明所有下游插件已消费文件。 |

私聊文件采用 UID-mode OIDB。目标响应的元数据 6/140 使用另一组标识，144 保留原 UUID，145 与原消息 `fileSubId` 对应，字段 100 的 16 字节与 `file10MMd5` 一致。解析保留 canonical 分支；采用原 UUID 分支时还必须匹配原 addon 或真实校验值，不能直接比较不同语义、不同长度的字段。重复字段、陌生 UUID、缺少配套校验、其他 hash 和未验证 URL 均拒绝。

经典 Offline 备用协议仍返回命令不匹配，不标记可用，不自动回退重发。当前通过范围为 UID-mode OIDB 和上述小文件样本，不能扩展为所有文件大小、目录及协议变体。

## 发送确认与合并发送

两个账号分别通过正式动作并发发送全新小文件，随后 `get_msg` 查询、实际下载及字节/SHA256 校验均通过。本轮明确覆盖了原故障条件：QQ 已提供精确成功送达回调，`sendMsg` 受理 Promise 仍 pending。修复后严格的当前会话、目标、UIN/UID、correlation、真实非零 uint64 ID 与 `sendStatus=2` 证明可以独立完成；单独受理成功不足以返回成功，明确拒绝优先失败，迟到响应不复活旧超时，未知动作不重发。

自定义本人文字/图片合并与真实合并读取保持独立可用。最终两个账号各发送一份新建两文字节点合并，经正式查询完整核对作者、顺序、空格、换行及两种返回形状。此前 AstrBot 含图发送有独立真实展示确认；最后一轮文字样本不冒充重新验证全部媒体。

已有 `node.data.id` 合并变体在当前 QQ 正式关闭。原生返回数值 0，消息实际送达且作者、时间、内容完整，但早期及最终回调都缺少能证明原请求到目标消息关联的标识。因此 `mergeExistingNative=false`，OneBot 和内部 `existingMerge` 均在查询、预留或原生派发前明确不支持。最终两账号请求分别在约 44/53 毫秒返回 1404，诊断没有新增原生尝试；不按正文、时间或同目标猜消息 ID，也不重发旧 tuple。该限制不影响 custom 新来源链路，且与文件受理 Promise 未结束的根因不同。

## 部署保留与剩余边界

最终镜像升级后两个账号均真实 ready、online、authorized，AstrBot 节点 connected；逐条核对升级前定位符到 OneBot ID 的映射全部保留，nextId 未倒退。只证明本轮新服务器已有状态保留，不宣称恢复未备份的旧服务器映射。

专用 Docker 服务 enabled/active，受控 daemon 恢复与容器恢复已有证据；没有执行整机重启。WAL、fsync、备份中断和回滚等异常主要由离线故障注入覆盖，没有对云端登录目录执行破坏性恢复或断电测试。

合并内语音、视频、引用以及其他未验证参数和权限边界继续明确保留。语音接收依赖真实账号内文件或经过验证的下载器；本地 `get_record` 导出路径不能当作跨容器下载 URL。目录存在、服务 ACK、QQ 接受和手机最终展示分别判断，具体限制见 [能力边界](capability-limits.md)。

QQApi 的解析补丁、固定 JSON 接线和离线结果单独记录，尚未完成其自身独立原生 sender 的全业务验收；不能沿用 Freshwater 的原生 rkey、下载或合并读取成功作为 QQApi 接线成功。
